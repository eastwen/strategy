## 🔑 关键技术细节（下次直接用）

### 富途 API 坑
- `get_capital_flow('HK.800000')` 不支持指数 → 用 `get_capital_distribution` 累加权重股
- `get_warrant` 必须用 `Request(stock_owner=, type_list=)` 不能直接传 symbol
- 港股代码识别要屏蔽 1xxxx-7xxxx（窝轮/牛熊证）

### CNN F&G API
- URL：`https://production.dataviz.cnn.io/index/fearandgreed/graphdata`
- Headers 需要 Referer + Origin 都指 `edition.cnn.com`
- Fallback 链：CNN → alternative.me crypto FNG → VIX 公式推算

### Put/Call 计算
- 用 yfinance Ticker('QQQ').option_chain(exp).calls/puts 累加 volume
- 取前 3 个到期日，按总成交量算 ratio
- 阈值：<0.7 看多 / 0.7-1.0 中性 / >1.0 看空

## 💡 教训（写给未来的我）

1. **被 east 抓到误读数据**：之前看到"42/50 都是 0"就误判 LLM 没工作，实际是 `TOP_LLM_N = 10` 只让 base_score 前 10 进 LLM。**下次先看代码再下结论，不要看到统计数字就脑补**。
2. **"重大利空触发分级减仓"是写死字符串**——日志/通知里出现的字符串不等于真发生了什么，必须看代码实际触发条件。
3. **数据流分叉是隐患重灾区**：飞书 vs 日报 vs JSON 三处展示同一事件时，**只要不是从同一个数据源 JOIN 出来的，就一定会漂移**。
4. **MEMORY.md 设计文档 ≠ 代码实现**——MEMORY 写"VIX 30% + FG 25% + PCR 25%"，代码实际是 VIX×2 = 100%。**设计文档必须用代码反推校对**。
5. **"今天的修复都是从此刻往后才生效"**——历史 22 条 open-positions、27 条 closed-trades 的 LLM 详情已经永远丢了，没法回填。下次设计新字段时优先考虑能不能从其他数据源（飞书消息、新闻库）反向回填。
