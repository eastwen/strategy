## NVDA 财报夜漏推送 — 根因 + 修复（commit e76d25c）

**east 13:16 问：NVDA 财报那么好为什么没推送？**

根因链（日志证据齐全）：
1. NVDA 财报发布于北京 8-27 04:05（美东 8-26 16:05 后），盘后 +4.7%。
2. us-scanner 每小时扫描，但**非常规时段所有报价源都给冻结的常规收盘价**（当日 -1.59%）。
3. 第一层 `calculate_score(-1.59%)` = 50 分 < 65 → `_build_quote_candidate` 返回 None → 静默丢弃。
4. 链路 5 源（finnhub→alphavantage→yfinance→longbridge→futu）全部只报常规价，全灭 → NVDA 整夜消失在第一层。
5. 白天 LLM 大量 429（doubao HTTP 429，今日 0-9 点每轮 700+ 次），另一独立问题待查。

**修复方案**（另一会话起草、east 修正方向"futu 有额度不要动顺序"、本会话完成）：
- 只升级链上第 3 位 yfinance：`includePrePost=true` + 5m K线，非常规时段取 postMarketPrice/preMarketPrice（盘前窗口 ET 4:00-9:30 优先 pre，防前日盘后残留价），基准=常规收盘价。
- 源顺序一字未动，futu 额度反而更省（财报股不再落到 futu）。
- 低于 65 分丢弃改为计数 + Top3 near-miss 留痕，每轮末尾打印汇总。
- 新增 `in_us_extended_session()`（ET 时区判断）。

**验证（夜盘实测）**：NVDA → price=219.53 (+4.71%) score=85 price_type=盘后 src=yfinance；
finnhub 冻结价 50 分被丢弃后链路自动落到 yfinance 接住；GE 常规路径不变；3 只迷你端到端 4.5s。

**效果推演**：财报夜当小时（北京 04:00/05:00 扫描）第一层 85 分 → 进五源 → ≥90 触发飞书推送。从漏 17 小时变当小时捕获。非交易时段只推不买，交易行为不变。

**测试坑（记给自己）**：单测 futu OpenQuoteContext 必须 ctx.close()，否则 SDK 非守护线程挂住解释器退出；stdout 重定向到文件是块缓冲，faulthandler exit=True 会吞掉未 flush 的完成日志，看起来像"扫描挂死"其实是测试装置问题。
