# 2026-06-15 auto-trader 两处修复

## 1. 非交易时段高价值信号 24h 冷却失效 → 持久化

**问题**：用户反馈"美股非交易时段高价值信号"反复推同一只股票。

**根因**：`auto-trader.py` ~1540 行已有 24h 冷却逻辑，但 `self.recently_closed` 是**进程内存字典**。cron 每 5 分钟重启进程，字典每次清空 → 冷却形同虚设。

**修复**（`strategy/auto-trader.py`）：
- 新增 `_load_notify_cooldowns()` / `_save_notify_cooldowns()`
- 落盘到 `data/notify-cooldowns.json`
- `__init__` 自动加载历史，推送后立即保存
- 只持久化 `opp_*` / `notify_*` 前缀键（不污染交易冷却 `recently_closed[symbol]`）
- 90 天过期清理 + 原子写（`.tmp` + `os.replace`）

**验证**：写入 → 重启进程 → 读取，`opp_TEST` 跨进程保留 ✅

## 2. "数量1，持仓0.00%" 废单问题 → 50%目标仓位守卫

**问题**：账户里出现 `US.GE qty=1 / US.TXN qty=1 / US.AMPH qty=6 / US.BIOA qty=10` 这种 0.00% 占比的鸡肋持仓。

**根因**（`auto-trader.py` ~1183 行）：
```python
allowed_value = min(target_value, max_single_value, max_total_value, cash)
raw_quantity = int(allowed_value / price)
# 只要 quantity >= 1 就放行 ❌
```
当 cash 紧张/总仓位上限快满时，`min(...)` 被钳到几百美元，`int(400/328) = 1` 股就成交了。

例子：总资产 $125万，目标仓位 12% (~$15万)，但 cash 只剩 $400 → 买 1 股 GE = 0.026%。

**修复**：仓位计算后加守卫
```python
if target_value > 0 and order_value < target_value * 0.5:
    return {'can_buy': False, 'reason': f'可下单${order_value:,.0f}({actual_pct:.2f}%) 不足目标${target_value:,.0f}({target_pct_disp:.2f}%)的50%，放弃废单'}
```

**特点**：
- 仍尊重**动态仓位**（评分→仓位、VIX 系数都不动）
- 守卫线 = 当次目标 × 50%，不是单票上限的 50%
- 评分 88 / VIX<20 → target $13.4万 → < $6.7万 放弃
- 评分 90 / VIX 25-30 (mult=0.5) → target $6.9万 → < $3.4万 放弃

## 3. ACDC -12.42% 止损过深 → 复核期硬止损

**用户问题**：为什么 ACDC 亏损 -12.42% 才触发止损？

**真因**：不是单一bug，是两个机制叠加：
1. cron `*/5` 检查频率 → 价格从 -5.09% 直接跳到 -6.94% 才触发首次
2. 触发后进入 30 分钟「分级减仓复核期」，期间无任何止损保护，剩余 50% 被动跌到 -12.61%

**修复**（`auto-trader.py` `process_staged_exit()`）：
复核期内累计 `pl_ratio*100 <= -10%` 时直接全平剩余仓位，不等 30 分钟到期。

```python
hard_stop_pl = float(pos_data.get('pl_ratio', 0)) * 100
if hard_stop_pl <= -10.0 and shares > 0:
    self.execute_position_sell(pos_data, shares, '复核期硬止损-10%全平', 'staged_hard_stop', market)
    return True
```

**特点**：保留"避免割在底"的设计意图，只兜底极端继续下杀的场景；旧的 30 分钟到期复核 / 收紧止损线逻辑都不动。
