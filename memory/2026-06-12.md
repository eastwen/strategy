## 💡 经验教训

### 我今天踩过的坑（记住别重犯）
1. **盲目自信汇报"完全正常"** → 用户一追问就发现卡了 5 小时没更新
2. **改逻辑不删旧痕** → 合并 cron 后没清文档里的旧文件名引用，被用户抓到
3. **解释时贴对照代码** → 用户以为旧 cron 还在 crontab 里
4. **遗漏 `should_scan()`** → 改了 cron timeout 但忘了代码里的"白天跳过"逻辑，导致 cron 触发但主动放弃扫描
5. **汇报"扫描在跑"但其实进程已退出** → 没核对 PID 实际状态
6. **修一处忘一处**：us-scanner.py L1075 修了 check_position_limits，L1106 的 opportunity=opp 没修

### 应该的工作流
- 改任何配置/代码前 → 先全局 grep 旧值
- 修复后 → 全文档/代码再 grep 一次确认零残留
- 汇报"正常"前 → 必须 ps + cat 文件 mtime 双重核对
- 用户问"是不是 X" → 不要直接答"是/否"，先验证再答
